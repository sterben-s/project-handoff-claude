# 恢复与接续

仅在用户要求从交接记录继续，或已获授权新建接续会话时读取。

## 1. 读取适用规则

按顺序读：工作区规则文件 → 项目 `AGENTS.md` → `CURRENT.md`。`references/` 下若有对应当前工作区的 `workspace-*.md`，一并读。只按需读专题资料，不默认全文加载历史。

## 2. 核对目标与授权

- 分清用户本次要求、记录里的目标、记录里的下一步。用户本次要求优先。
- 旧记录、旧计划、旧授权不自动恢复；只核对仍有效的部分。
- 需要授权才能继续的动作（提交、推送、部署、安装、付费、删除、对外发送）单独确认。

## 3. 核对现场

只查影响第一步的事实，不扩大成全量审计：

- 目录、Git 根目录、分支、HEAD、工作树、未提交改动及归属；记录写的“是否 fetch”是否仍成立。
- 关键成果和证据文件是否存在、是否仍是当前版本。
- 运行中的服务、端口、任务用现场命令核对，不沿用旧 PID、旧登录或旧进程假设。
- 非 Git 项目核对文件时间、原件和输出位置。

## 4. 报告差异

用简短一段报告：目标、进度、未决、发现的差异（记录与现场不一致处）、第一步。只在缺授权或关键取舍时提问；能从文件核实的自行核实。

## 5. 继续或停

- 用户已明确要求继续，且授权覆盖第一步：直接推进，不重复索要已取得的授权。
- 只要求查看：只读核对，不改文件。
- 缺授权、缺关键材料或存在用户取舍：停在边界，说明缺什么。

## 6. 新建接续会话

只有用户明确要求或确认了具体提议才执行。

在本应用内且 `mcp__ccd_session__start_session` 可用时：

1. 准备自包含简报（见下），不复述整段聊天。
2. 用 `context: "fresh"` 新建，不用 `fork`。
3. 默认让新会话共享当前工作树，以便看到未提交改动；需要隔离分支时才用独立 worktree，并说明。
4. 告诉用户传入了哪些上下文、新会话是否已创建；创建失败或工具不可用时保留材料，给出手动开场白。

简报模板：

```text
读取 <项目绝对路径>/AGENTS.md 与 CURRENT.md 的“当前接续”。项目 <绝对路径>；目标 <…>；当前进度 <…>；限制 <…>；第一步 <…>；验收 <…>。先只读核对目录、版本和证据，报告差异后继续；不要执行未授权动作。
```

没有该工具（Claude Code CLI 或其他宿主）时，只交付开场白，说明需用户手动新建会话，不宣称已自动接续。

## 7. 更新记录

- 只读核对阶段不改记录。
- 接手方完成第一个实际动作后，才把“当前接续”的状态改为“已接手（日期）”，并更新进度；不要提前宣称恢复成功。
- 不删除旧记录；失效内容标为历史或被新条目替代。
