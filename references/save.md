# 保存交接

仅在用户要求保存、整理交接，或项目规则要求在阶段完成、验收、阻塞、换会话前维护 `CURRENT.md` 时读取。

## 1. 选择入口

1. 用户指定了文件或目录，按指定位置保存。
2. 否则使用项目现有 `CURRENT.md`。
3. 没有 `CURRENT.md` 时，先判断跨会话接续是否真的需要。需要才在项目根目录按 [模板](../assets/current-handoff.template.md) 建立 `CURRENT.md`；不需要就只在回复中交付接续内容和开场白。
4. 不写到工作区根目录、`outputs/`、`tmp/` 或无关项目；不新建第二套状态文件。

## 2. 只维护一个“当前接续”区

- 文件开头是 `# 标题` 和更新日期时，把 `## 当前接续` 放在它们之后。
- 已有 `## 当前接续`：整段替换，不追加新的卡片，不保留旧版本副本。
- 文件已经采用结构化分区（如 `## 目标与范围`、`## 状态与证据`）：在原分区内更新，并在顶部补更新日期；不要再加一个平行区。
- 文件是流水账（如 `## 当前进度` 下按日期堆条目）：在标题后插入 `## 当前接续`，历史条目原样保留。
- 不批量删除、迁移或改写历史条目；发现其他会话或批次的新内容，保留并在必要时合并相关行。
- 改前重读目标段落；若已被其他会话修改，先合并差异，不能用旧副本覆盖。

## 3. 写什么

按 [模板](../assets/current-handoff.template.md)，默认 10–15 行：

| 字段 | 记录方式 |
| --- | --- |
| 更新 | 日期；一句“记录不新增授权；现场须重新核对” |
| 目标 / 验收 | 一句话目标；做到什么算完成 |
| 进度与证据 | 已完成（结果 + 证据路径或链接）；进行中 |
| 验证 / 用户验收 | 已执行什么、结果；未执行什么；用户是否验收 |
| 决定 | 用户已确认；待决定或 Agent 建议；已否决及原因 |
| 未完成 / 阻塞 | 未做、未验证、阻塞项 |
| 授权边界 | 已授权动作；未授权或不明确动作 |
| 写入归属 | 本会话负责的文件；未提交改动的归属；只在存在并发或多工作树时写 |
| 现场快照 | 日期、目录、分支/HEAD、工作树、是否 fetch；非 Git 项目省略 |
| 下一步 | 1–3 条可执行动作，每条带验收方法 |

可选：交接编号 `PH-YYYYMMDD-简称-NN`、开场白、已否决路线。只有能防止重复劳动或交接歧义时才加。

## 4. 证据与边界

- 只记录能从现场或已有记录核实的事实；推断和假设标明。
- 未执行的检查写“未执行”，不写“通过”；局部验证不写成完整验收。
- 不写凭据、Token、Cookie、SSH 私钥、完整日志或聊天全文；测试账号只写凭据所在文件的位置，不写实际密码。
- 不把候选下一步写成已授权；不把用户未确认的方案写成决定。

## 5. 回读核对

写入后回读：路径正确、只改了当前区、其他条目还在、关键决定与下一步和用户要求一致、引用可访问。缺失文件或不可访问的引用要明确报告，不能默认已保存。

## 6. 提交与授权

保存交接本身不附带 commit、push、部署、安装或删除。项目规则要求每次改动后本地提交的，按项目规则和当前授权另行处理；记录未提交原因和归属。

## 7. 开场白

保存后交付可直接粘贴的开场白：

```text
/project-handoff 恢复。项目 <绝对路径>；来源 <CURRENT.md> 的“当前接续”；目标 <…>；限制 <…>；第一步 <…>；验收 <…>。先只读核对再继续。
```

没有 `/project-handoff` 入口的宿主，改成“读取 <文件> 的当前接续，核对后继续”。不要把它写成“已自动接续”。
