# 适配到自己的工作区

本技能默认假设：交接记录写在项目 `CURRENT.md`，项目规则优先于技能。做法不同时，按本页补一份工作区适配，而不是改技能的正文。

## 1. 先找到规则在哪

按顺序找，找到就停，不要重复读同一层：

1. 仓库上层有没有工作区规则（如 `AGENTS.md`、`CLAUDE.md`、`README.md` 里的协作说明）；
2. 项目根有没有 `AGENTS.md`；
3. 有没有现成的交接载体（`CURRENT.md`、`docs/status.md`、issue 模板等）。

只有第一层是“多项目共用”的时候才需要单独写适配页；单一仓库的项目直接在项目 `AGENTS.md` 里说明即可。

## 2. 只有这几件事需要写清楚

| 事项 | 为什么必须明确 |
| --- | --- |
| 规则入口 | 新会话要知道读哪几个文件、以哪个为准 |
| 记录载体 | 交接写进哪个文件；没有就说明是否新建 |
| 单一当前区 | 已有流水账时，当前状态写在哪里、历史条目是否保留 |
| 凭据位置 | 只写位置，不写密码；避免有人把密码写进交接记录 |
| 提交与推送 | 保存交接是否顺带提交；推送是否另行授权 |
| 并发写入 | 多个会话或多人时，同一文件谁写、发现了别人的改动怎么办 |

其余内容（目录职责、验证门槛、发布流程）应留在项目自己的规则里，不要在适配页复制一遍。

## 3. 文件怎么放

- 命名 `references/workspace-<名字>.md`，按项目或工作区命名，例如 `workspace-myteam.md`；
- 页首写清“仅在什么情况下读取”，避免每个会话都加载；
- 只指路，不复制规则正文；与项目规则冲突时以项目规则为准；
- 一份适配页对应一个工作区，不为每个项目各建一份。

## 4. 一个最小例子

```md
# myteam 工作区适配

仅在当前项目位于 `D:\work\myteam` 下时读取。

## 规则入口
- 工作区规则：`D:\work\myteam\AGENTS.md`
- 项目规则：`<项目>\AGENTS.md`
- 项目短交接：`<项目>\CURRENT.md`

## 记录约定
- 只在项目内写 `CURRENT.md`，不写到工作区根目录。
- 已有 `## 当前接续` 就整段替换；历史条目保留。
- 凭据统一在 `~/.myteam/accounts.json`，记录只写位置。

## 提交
- 保存交接不自动 commit；提交按本次授权单独处理。
```

## 5. 和别的工具共用一个记录

同一个项目可能同时被 Claude Code、Codex 或其他工具使用：

- 共用项目里的 `CURRENT.md`，只维护一个 `## 当前接续` 区；
- 各自的技能目录、状态目录、钩子配置互不读取对方，也不写对方的状态目录；
- 不要让两个会话同时写同一区；发现归属不明的改动先暂停写入、核对后再继续；
- 不要为每个工具各建一份 `PROJECT_STATE.md` 之类的并行状态，那会立刻产生两份互相过期的“当前”。
